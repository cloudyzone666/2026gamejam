name: unity-fix-explainer
description: 当我提出代码问题或希望调整某个功能时，请先进入代码分析模式，不要直接修改文件。
---


请按以下步骤执行：

1. **定位代码**
   - 找出涉及的脚本、类、方法和关键代码行。
   - 说明这些代码分别负责什么。
   - 梳理相关方法之间的调用关系，以及涉及的其他系统。

2. **解释实现原理**
   - 用适合 Unity 初学者的语言解释当前实现。
   - 解释涉及的 C# 语法、Unity API 和设计模式。
   - 说明当前代码为什么会产生我描述的现象。

3. **分析修改方案**
   - 提供最小改动方案。
   - 说明修改前后的行为区别。
   - 指出可能影响的其他功能和潜在风险。
   - 如果现有架构存在问题，说明是否应该重构，而不是只做表面修补。

4. **等待我的决定**
   - 此阶段只分析，不修改任何文件。
   - 不创建脚本、不删除代码、不执行自动修复。
   - 等待我明确批准具体方案。

5. **获得批准后的实施**
   - 尽可能只修改必要代码。
   - 保留现有架构和已经正常工作的功能。
   - 修改后进行必要的编译、测试和代码复核。
   - 汇报修改文件、修改内容、测试结果及尚存风险。

特别要求：不要为了实现一个小需求就随意重写整个系统。优先理解现有项目，再决定如何修改。
